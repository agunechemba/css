Getting started with CSS

Three ways to bring style to a page — and why one of them is the one you want.

CSS can be attached to a page in three ways. The first and best is the external stylesheet: a separate .css file linked from the <head> with a <link> element whose rel is "stylesheet" and whose href points to the file. Because the same file can be reused across every page of a site, changing one colour there changes it everywhere.

The second way is internal styles: a <style> block inside the <head>. It works, but only for the page it lives in. The third is inline styles: a style attribute on the element itself. Inline styles override everything, which makes them useful for email templates and quick debugging but poor for maintainable work.

Two further tools round out the family. The @import rule pulls in another stylesheet from inside a stylesheet; and JavaScript can change any element's styles by reaching into its style property — el.style.opacity = 0.5, or el.style.fontFamily = 'sans-serif'.

<!DOCTYPE html>
<html>
  <head>
    <link rel="stylesheet" type="text/css" href="style.css">
  </head>
  <body>
    <h1>Hello world!</h1>
    <p>I ♥ CSS</p>
  </body>
</html>

Put the <link> in the <head>, before the elements it styles, or the browser will flash unstyled content while it waits for the CSS to arrive.

Key Ideas

  • External stylesheets are the recommended way to apply CSS — one file, many pages.
  • Internal styles live in a <style> block inside the document; inline styles live on the element itself.
  • @import brings in another stylesheet from inside a stylesheet.
  • JavaScript can read and change any element's styles through its style property.

Structure and Formatting of a CSS Rule

Selectors, declarations, and the commas that bind them.

A CSS rule has two parts: a selector that names what to style, and a declaration block (curly braces) containing one or more declarations. Each declaration is a property, a colon, a value, and a semicolon — h1 { color: green; }.

Some properties take a property list: multiple values separated by commas. text-shadow: yellow 0 3px, green 4px 4px 10px; paints two shadows. The order matters. Others take shorthand values — margin: 10px 15px is the same as margin: 10px 15px 10px 15px.

When several selectors share the same declarations, group them with a comma. div, p { color: blue } styles every div and every paragraph. Without the comma, div p { color: blue } would style only paragraphs inside divs.

/* One rule, several selectors */
div, p, .blue, #first, div span {
  color: blue;
}

/* One rule, several values */
span {
  text-shadow: yellow 0 3px, green 4px 4px 10px;
}

Read rules from the selector inward. The selector decides which elements are touched; the declarations decide how. Get the shape of a rule right, and every page that follows becomes easier.

Key Ideas

  • A rule is a selector plus a declaration block.
  • Group selectors with commas to share declarations.
  • Some properties take comma-separated value lists.
  • Shorthand properties abbreviate several longhands in one declaration.

Comments

Notes to your future self, invisible to the browser.

CSS comments begin with /* and end with */. Anything between them is ignored by the browser, which makes comments the perfect place to leave a note, disable a declaration while debugging, or section off a long stylesheet.

Comments can stand on their own or sit inside a rule. They can span one line or many. There is no single-line // comment in CSS — that syntax belongs to JavaScript, Sass, and Less, not to plain stylesheets.

/* This is a CSS comment */
div {
  color: red;
  /* This is also a CSS comment */
}

/*
   Multiple-line comment.
   Useful for disabling a block while debugging.
*/

A well-placed comment costs a few keystrokes and saves a future reader ten minutes. Use them to explain why, not what — the browser already knows what.

Key Ideas

  • Comments use /* … */; CSS has no // single-line comment.
  • Comments can sit outside or inside a declaration block.
  • Use comments to explain reasoning, not to restate the code.

  1. Comment out the color declaration in a rule and reload the page.

Selectors

How CSS knows which element you mean.

Selectors are the address system of CSS. The universal selector * matches every element. A tag selector matches a tag — div, p. A class selector matches any element with that class — .blue. An ID selector matches one element with that ID — #headline — and IDs must be unique on the page.

Attribute selectors match on the presence or value of an attribute: [disabled], [type="checkbox"], [href$=".pdf"], [lang|="en"]. Combinators describe relationships: div span (any descendant), div > span (direct child), a + span (immediately following sibling), a ~ span (any following sibling).

Pseudo-classes select by state or position — :hover, :visited, :first-child, :nth-child(3), :not(.example). Pseudo-elements style a part of an element — ::before, ::after, ::first-letter.

/* Attribute selector */
input[type="checkbox"] { accent-color: green; }

/* Child combinator */
nav > a { text-decoration: none; }

/* Pseudo-class */
a:hover { text-decoration: underline; }

/* Pseudo-element */
p::first-letter { font-size: 2em; }

/* Negation */
input:not([disabled]) { background: #fff; }

Selectors can be combined: div.card.warning matches a div with both classes; #main .title matches titles inside the element with id main.

Key Ideas

  • Basic selectors: *, tag, .class, #id.
  • Attribute selectors match on presence or value; combinators express relationships.
  • Pseudo-classes select by state or position; pseudo-elements style sub-parts.
  • Combine selectors to narrow the match — div.card.warning.

Backgrounds

Colours, gradients, images, and the shorthand that ties them together.

The background-color property paints a solid colour behind an element. Colours can be keywords (red), hex codes (#ff0000), rgb()/rgba(), or hsl()/hsla(). The transparent keyword is the default; inherit and initial also work.

Gradients are new image types introduced in CSS3. linear-gradient() flows in a direction; radial-gradient() radiates from a centre. Both have repeating variants. background-image accepts one or many url() references; multiple images stack in declaration order.

The shorthand background sets colour, image, position, size, repeat, origin, clip, and attachment in one declaration. Order does not matter, but the shorthand resets every previously set background property, so use longhands when you only want to tweak one.

.gradient {
  background: linear-gradient(to left, red, blue);
}

.pattern {
  background: url('pattern.png') green repeat top left;
}

.hero {
  background: #000000 url("hero.jpg") center / cover no-repeat fixed;
}

background-size offers cover (fill, cropping) and contain (fit, letterboxing) when you need to keep the aspect ratio without picking exact pixels.

Key Ideas

  • Colours can be keywords, hex, rgb(a), or hsl(a).
  • Gradients are images; use them with background-image or the shorthand.
  • Multiple url() values stack in order.
  • The background shorthand resets every background property — use longhands to tweak.

Centering

Five reliable ways to put something in the middle.

Centring horizontally is easy: text-align: center for inline content, margin: 0 auto for block elements with a defined width, and display: flex; justify-content: center; for flex containers. Centring vertically used to be hard; now it is a one-liner.

The most flexible modern recipe is Flexbox: display: flex; align-items: center; justify-content: center; on the parent centres both axes. The transform: translate(-50%, -50%) technique works without a parent flexbox, positioning the element absolutely at 50% from the top and left and then pulling it back by half its own size.

Older techniques still earn their keep. line-height equal to the container height centres a single line of text. display: table plus display: table-cell; vertical-align: middle; centres anything, and the ghost-element trick (a ::before with height 100%) works when heights are unknown.

/* Flexbox — the modern favourite */
.container {
  display: flex;
  align-items: center;
  justify-content: center;
}

/* Transform — absolute and self-sizing */
.centered {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}

Pick the technique that matches the layout you already have. If you are using Flexbox elsewhere, use Flexbox. If the element must float free of its parent, use the transform trick.

Key Ideas

  • text-align centres inline content; margin: 0 auto centres blocks with widths.
  • Flexbox centres both axes with two declarations.
  • The transform trick works without a flex parent.
  • Table display and ghost elements handle unknown heights.

The Box Model

Every element is a rectangle — and its edges have names.

Every element the browser lays out becomes a rectangle with four edges: the content at the centre, the padding around it, the border around the padding, and the margin around the border. The full distance an element occupies is content plus padding plus border plus margin.

By default, width and height describe the content box only. That means a width: 100% textarea with padding: 3px overflows its parent by 6 pixels. The box-sizing property fixes this: border-box makes width and height include padding and border, so width: 100% stays inside its container.

/* The global border-box fix */
html {
  box-sizing: border-box;
}
*, *:before, *:after {
  box-sizing: inherit;
}

/* Now width means the visible width */
textarea {
  width: 100%;
  padding: 3px;
}

Margins collapse vertically: two adjacent vertical margins merge into the larger of the two. Horizontal margins do not collapse. Padding never collapses. Understanding this keeps seemingly mysterious layout gaps from appearing between sections.

Key Ideas

  • Four edges: content, padding, border, margin.
  • box-sizing: border-box makes width and height include padding and border.
  • Vertical margins collapse; horizontal margins do not.
  • Padding never collapses.

Margins

The space outside the border — and the collapsing that surprises everyone.

Margins are the empty space outside an element's border. The shorthand margin takes one to four values (top, right, bottom, left). Individual properties — margin-top, margin-right, margin-bottom, margin-left — adjust one side at a time.

The most famous quirk is margin collapsing. Two vertical margins that touch merge into the larger of the two, not the sum. Two horizontal margins do not collapse — a 10px left margin next to a 10px right margin produces 20px of space. Parent and first-child top margins also collapse, which is why a margin-top on a heading sometimes seems to escape its container.

Margins can be set to auto to centre blocks horizontally, and they can be negative to overlap elements without absolute positioning. Percentage margins — top and bottom included — are calculated from the parent's width, not its height, which is another common source of confusion.

/* Centre a block horizontally */
#myDiv {
  width: 80%;
  margin: 0 auto;
}

/* Negative margin overlaps */
#over {
  margin-left: -20px;
}

/* Four-value shorthand */
p {
  margin: 0 10px 50px 100px; /* top right bottom left */
}

Choose longhand when you only want to adjust one side; choose shorthand when setting all four. Consistent margin habits keep vertical rhythm predictable.

Key Ideas

  • Margin is the space outside the border; margin: 0 auto centres blocks horizontally.
  • Vertical margins collapse; horizontal margins do not.
  • Percentage margins on top/bottom are based on the parent's width.
  • Negative margins can overlap elements without absolute positioning.

Padding

The space inside the border — where content gets room to breathe.

Padding is the space between an element's content and its border. Unlike margin, it lives inside the box, so it takes the element's background colour with it. The shorthand follows the same order as margin — top, right, bottom, left — and can take one to four values.

Padding never collapses. Two elements stacked vertically do not share or merge their padding. This makes it a reliable tool for creating interior breathing room. Negative padding is not allowed.

/* All four sides */
.pad-all { padding: 25px; }

/* Vertical then horizontal */
.pad-two { padding: 25px 50px; }

/* Top, horizontal, bottom */
.pad-three { padding: 25px 50px 75px; }

/* Top right bottom left */
.pad-four { padding: 25px 50px 75px 100px; }

/* One side only */
.pad-top { padding-top: 5px; }

The easiest way to remember the four-value shorthand is the word "TRouBLe" — Top, Right, Bottom, Left. Get that order right and the rest of CSS's box-property shorthands fall into place.

Key Ideas

  • Padding is inside the border and carries the background.
  • Shorthand order: top, right, bottom, left (TRouBLe).
  • Padding never collapses; negative values are not allowed.
  • Longhand properties adjust one side at a time.

Border

Lines, curves, images, and the shorthands that build them.

The border property draws a line around the element. The most common shorthand — border: 1px solid #000; — sets width, style, and colour together. Styles include solid, dashed, dotted, double, groove, ridge, inset, outset, none, and hidden.

border-radius rounds corners. One value rounds all four equally; two values give horizontal and vertical radii; eight values fine-tune each corner. Setting border-radius: 50% on a square produces a circle.

Borders can also be built from images. border-image slices a source image into nine regions and stretches the edges to fit. For multiple borders, layer an outline, a box-shadow, or a pseudo-element behind the border.

/* Basic border */
div {
  border: 1px solid #000;
}

/* Rounded corners */
.circle {
  width: 200px;
  height: 200px;
  border-radius: 50%;
}

/* Multi-coloured border with an image */
.fancy {
  border-image: linear-gradient(
    to right,
    red 20%, green 20%, green 40%,
    blue 40%, blue 60%
  ) 1;
}

For tables, border-collapse: collapse merges adjacent cell borders into a single line. The alternative — separate — keeps them apart and allows border-spacing to control the gap between cells.

Key Ideas

  • border shorthand sets width, style, and colour together.
  • border-radius: 50% turns a square into a circle.
  • border-image slices an image into nine regions.
  • border-collapse merges adjacent table borders.

Outlines

A line outside the border that takes up no space.

An outline is a line drawn around an element, outside its border. The crucial difference from a border is that outlines do not take up space in the box model — adding one does not shift the element or its neighbours. That makes outlines ideal for focus rings and debugging without disturbing layout.

Outlines accept the same styles as borders: solid, dashed, dotted, double, groove, ridge, inset, outset, none, and hidden. Unlike borders, outlines cannot have rounded corners, and in some browsers they may be non-rectangular if the element contains text at different font sizes.

/* Outline shorthand */
button:focus {
  outline: 2px solid #2a7f7a;
}

/* Different styles */
.p1 { outline-style: dotted; }
.p2 { outline-style: dashed; }
.p3 { outline-style: solid; }
.p4 { outline-style: double; }

Browsers give focusable elements a default outline. Removing it with outline: none without providing an alternative hurts keyboard accessibility — always replace it with something visible.

Key Ideas

  • Outlines are drawn outside the border and take up no space.
  • They accept the same styles as borders but cannot be rounded.
  • Use them for focus rings and layout debugging.
  • Never remove a focus outline without providing a replacement.

Overflow

What to do when content is bigger than its box.

The overflow property decides what happens when content spills past its container. visible (the default) lets it spill; hidden clips it; scroll adds scrollbars; auto adds scrollbars only when needed. overflow-x and overflow-y control the axes separately.

overflow-wrap: break-word tells the browser it may break a long word onto multiple lines to keep it inside its container — invaluable for user-generated content and URL-like strings. Without it, a single long word can break a narrow layout.

Setting overflow to anything other than visible creates a block formatting context. That is why overflow: hidden on a parent can force it to contain its floated children — a fact that underpins several classic layout hacks.

/* Scroll always */
.scroll {
  width: 100px;
  height: 100px;
  overflow: scroll;
}

/* Auto — scrollbars only when needed */
.auto {
  overflow: auto;
}

/* Break long words */
.wrap {
  overflow-wrap: break-word;
}

/* Contain floats */
.parent {
  overflow: hidden;
}

Use overflow: hidden deliberately, not as a fix-all. It clips content, including shadows and outlines, which sometimes causes unexpected visual bugs.

Key Ideas

  • overflow controls what happens when content overflows.
  • overflow-wrap: break-word breaks long words.
  • Any non-visible overflow creates a block formatting context.
  • Axis-specific properties are overflow-x and overflow-y.

Media Queries

Different styles for different screens — the heart of responsive design.

A media query applies CSS rules only when a condition is met. The condition can describe the media type (screen, print, all) and one or more features: width, height, orientation, resolution, colour capabilities, and more.

The basic form is @media screen and (max-width: 600px) { … }. The not and only modifiers extend the syntax. Media queries are dynamic: when the viewport changes, the styles switch on and off in real time.

Common breakpoints cluster around phone (under 480px), tablet (480–1023px), and desktop (1024px and up). Retina displays can be targeted with -webkit-min-device-pixel-ratio: 2 or min-resolution: 192dpi.

/* Phone styles */
@media only screen and (max-width: 480px) {
  .title { font-size: 80%; }
}

/* Tablet styles */
@media only screen and (min-width: 481px) and (max-width: 1023px) {
  .title { font-size: 90%; }
}

/* Desktop styles */
@media only screen and (min-width: 1024px) {
  .title { font-size: 120%; }
}

/* Print styles */
@media print {
  .no-print { display: none; }
}

Always pair width-based queries with the viewport meta tag — <meta name="viewport" content="width=device-width, initial-scale=1"> — or mobile browsers will render at a virtual width that defeats the query.

Key Ideas

  • Media queries apply CSS conditionally on screen features.
  • min-width and max-width define breakpoints; not and only refine them.
  • Retina screens are detected with device-pixel-ratio or resolution queries.
  • The viewport meta tag is required for width-based queries on mobile.

Floats

The classic way to wrap text around an image — and the layout it accidentally enabled.

float: left and float: right push an element to one side of its container, allowing other content to flow around it. The canonical example is a magazine-style image with text wrapping around it.

Floats were once used to build entire column layouts, but the property was never designed for that. Floated elements are removed from normal flow, which is why a parent with only floated children collapses to zero height. The clear property (clear: both) prevents an element from sitting beside a float.

To contain floats, use a clearfix — a pseudo-element that clears the float inside the parent — or set overflow: hidden on the parent, which creates a block formatting context.

/* Wrap text around an image */
img {
  float: left;
  margin-right: 1rem;
}

/* Clearfix */
.cf::before,
.cf::after {
  content: " ";
  display: table;
}
.cf::after {
  clear: both;
}

/* Two-column layout with floats */
.sidebar { width: 150px; float: left; }
.content { width: 450px; float: right; }

Modern layouts use Flexbox and Grid instead of floats. But floats still shine for their original job: letting text flow around images and pull-quotes.

Key Ideas

  • Floats push an element to one side and let content wrap around it.
  • Floated elements are removed from normal flow; parents collapse without a clearfix.
  • clear prevents an element from sitting beside a float.
  • Use Flexbox or Grid for page layout; keep floats for text wrapping.

Typography

Fonts, sizes, spacing, shadows — the properties that make text feel right.

The font shorthand bundles style, variant, weight, size/line-height, and family into one declaration: font: bold 20px Arial, sans-serif;. Only font-size and font-family are required — if either is missing, the shorthand is ignored.

Font sizes accept any length unit. text-align sets horizontal alignment. line-height sets vertical rhythm. letter-spacing (tracking) and word-spacing adjust the space between letters and words. text-transform changes case. text-decoration adds or removes underlines, overlines, and line-throughs.

Font stacks list fallbacks in order: font-family: 'Segoe UI', Tahoma, sans-serif; tries each face until one is available. text-shadow adds one or more shadows — text-shadow: 2px 2px 10px #0000FF; — with blur and colour controls.

/* Font shorthand */
h1 {
  font: bold 20px Arial, sans-serif;
}

/* Font stack */
body {
  font-family: 'Segoe UI', Tahoma, sans-serif;
}

/* Text shadow */
h1 {
  text-shadow: 2px 2px 10px #0000FF;
}

/* Text overflow with ellipsis */
.text {
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}

Typography is where CSS meets design. Learn the properties, then practise restraint: a page with two fonts and consistent spacing almost always reads better than one with five.

Key Ideas

  • font shorthand requires font-size and font-family.
  • Font stacks list fallback families in order.
  • text-shadow takes horizontal, vertical, blur, and colour.
  • text-overflow: ellipsis truncates overflowing text.

Flexible Box Layout (Flexbox)

A one-dimensional layout model that expands, shrinks, and aligns.

Flexbox lays out items in one direction — a row or a column — and distributes the space among them. Apply display: flex to a container and its immediate children become flex items. flex-direction chooses the axis; justify-content aligns along that axis; align-items aligns across it.

justify-content: center and align-items: center together centre both axes in two declarations. flex-wrap: wrap lets items wrap to a new line when the row runs out of space. flex-grow, flex-shrink, and flex-basis (usually abbreviated as flex) control how items grow and shrink.

Flexbox shines for navigation bars, sticky footers, card grids, and the "Holy Grail" layout (header, footer, and three-column centre). It is also the modern answer to vertical centring.

/* Centre everything */
.aligner {
  display: flex;
  align-items: center;
  justify-content: center;
}

/* Sticky footer */
body {
  display: flex;
  flex-direction: column;
  min-height: 100vh;
}
.content {
  flex: 1 0 auto;
}
.header, .footer {
  flex: none;
}

/* Buttons aligned to card bottoms */
.card {
  display: flex;
  flex-direction: column;
}
.card p:last-child {
  margin-top: auto;
  text-align: center;
}

Flexbox is supported by every modern browser, with vendor prefixes needed only for very old versions of Safari and IE10.

Key Ideas

  • display: flex turns a container into a flex layout.
  • justify-content aligns along the main axis; align-items across it.
  • flex-grow, flex-shrink, and flex-basis control sizing.
  • Flexbox replaces floats for most one-dimensional layouts.

Cascading and Specificity

When rules collide, which one wins?

When several rules set the same property on the same element, the browser resolves the conflict with two mechanisms: specificity and the cascade. Specificity scores each selector on three axes — IDs (A), classes/attributes/pseudo-classes (B), and types/pseudo-elements (C). An ID beats any number of classes; a class beats any number of types.

If specificity ties, the cascade takes over: later rules win. Inline styles beat every selector, and !important beats inline styles. The !important flag is powerful and dangerous — use it sparingly and never as a substitute for structure.

Stylesheets load in order: user agent styles, then user styles, then author styles, then inline styles. Within the author styles, later declarations override earlier ones of equal specificity.

/* Specificity: 0,1,0 */
.bar { color: red; }

/* Specificity: 0,0,1 */
div { color: blue; }

/* Specificity: 0,2,0 — wins */
.bar.bar { color: green; }

/* Inline style beats everything */
<div style="color: purple;">…</div>

/* !important overrides inline */
p { color: orange !important; }

The best stylesheet keeps specificity low and flat. If you find yourself stacking classes or reaching for !important, restructure the selectors instead.

Key Ideas

  • Specificity is scored as A (IDs), B (classes/attributes), C (types).
  • An ID beats any number of classes; a class beats any number of types.
  • Later rules win when specificity ties.
  • Inline styles beat selectors; !important beats inline styles.

Colors

Keywords, hex, rgb, hsl — and the currentColor that ties them together.

CSS accepts colours in four main notations. Keywords — red, teal, rebeccapurple — are readable and memorable. Hex codes — #ff0000, or the short form #f00 — encode red, green, and blue as pairs of hexadecimal digits. rgb() and rgba() use decimal numbers 0–255, with an optional alpha between 0 and 1. hsl() and hsla() use hue (0–360°), saturation, and lightness percentages.

The keyword currentColor takes the current element's color value and reuses it — perfect for borders and backgrounds that should match the text. The transparent keyword is a fully-transparent black.

/* All the same colour */
p { color: red; }
p { color: #ff0000; }
p { color: #f00; }
p { color: rgb(255, 0, 0); }
p { color: hsl(0, 100%, 50%); }

/* Semi-transparent */
p { color: rgba(255, 0, 0, 0.5); }
p { color: hsla(0, 100%, 50%, 0.5); }

/* Match the text colour */
.card {
  color: #b00;
  border: 2px solid currentColor;
}

Use hex for static palettes, hsl() for programmatic colour manipulation, and currentColor to keep related properties in step.

Key Ideas

  • Colours can be keywords, hex, rgb(a), or hsl(a).
  • Hex pairs encode red, green, and blue; #f00 is shorthand for #ff0000.
  • rgba() and hsla() add an alpha channel.
  • currentColor reuses the element's computed color.

Opacity

Making an element see-through — without surprising its children.

The opacity property accepts a number between 0 and 1. 1 is fully opaque, 0 is fully transparent, and anything between is a blend. The property affects the element and everything inside it, which is usually what you want for a card or a modal overlay.

When only the background should be transparent, use an rgba() or hsla() background colour instead. Setting opacity on the parent makes its children transparent too; setting an alpha background colour leaves the content solid.

/* Whole element, children included */
.overlay {
  opacity: 0.6;
}

/* Background only, content stays solid */
.panel {
  background-color: rgba(0, 0, 0, 0.6);
}

/* Legacy IE fallback */
.legacy {
  filter: alpha(opacity=60);
  opacity: 0.6;
}

Old versions of Internet Explorer need the filter: alpha(opacity=…) fallback, where the value is 0–100 rather than 0–1.

Key Ideas

  • opacity takes a number from 0 (transparent) to 1 (opaque).
  • It affects the element and all its children.
  • For a transparent background only, use rgba() or hsla().
  • Legacy IE uses filter: alpha(opacity=…).

Length Units

Pixels, ems, rems, viewport units — choosing the right ruler.

CSS lengths come in two families: absolute and relative. Absolute units — px, cm, mm, in, pt, pc — map to physical or pseudo-physical sizes. Relative units — em, rem, %, vh, vw, vmin, vmax, ch, ex — depend on the element or the viewport.

em is relative to the element's own font-size (or inherited). rem is relative to the root <html> font-size, which makes it excellent for global scaling. vh and vw are percentages of the viewport's height and width; vmin and vmax choose the smaller or larger dimension.

html { font-size: 16px; }

h1 { font-size: 2rem; }   /* 32px */
p  { font-size: 1rem; }   /* 16px */
li { font-size: 1.5em; }  /* 24px, compounding */

.hero {
  width: 20vw;
  height: 20vh;
}

The rem unit is the modern default for typography because it does not compound. em is still useful inside a component whose size should scale with its own font-size.

Key Ideas

  • Absolute units include px, cm, mm, in, pt, pc.
  • Relative units include em, rem, %, vh, vw, vmin, vmax.
  • em compounds; rem does not.
  • vh/vw are percentages of the viewport.

Pseudo-Elements

Pseudo-elements select sub-parts of an element. ::first-letter and ::first-line style the first letter or line of a block. ::before and ::after insert generated content before or after the element's content — but only if you give them a content value.

Because they are generated by CSS, pseudo-elements cannot be selected or copied in the usual way, and they do not appear in the DOM. They are useful for decorative flourishes, custom bullets, and clearfixes.

/* Drop cap */

  color: #a43f2a;
  float: left;

  display: inline-block;
  width: 10px;
  height: 10px;
  margin-right: 10px;

Positioning

Static, relative, absolute, fixed — and the z-index that stacks them.

The position property decides how an element is placed. static is the default: the element flows normally and top/right/bottom/left do nothing. relative shifts the element from its normal position. absolute removes it from flow and positions it against its nearest positioned ancestor. fixed positions it against the viewport.

The z-index property controls stacking order among positioned elements. Higher values appear in front; the default is auto. z-index only applies to positioned elements (relative, absolute, fixed) or flex/grid items.

/* Stacked boxes */
div {
  position: absolute;
  width: 200px;
  height: 200px;
}
#div1 { z-index: 1; left: 0; top: 0; background: blue; }
#div2 { z-index: 3; left: 100px; top: 100px; background: green; }
#div3 { z-index: 2; left: 50px; top: 150px; background: red; }

/* Sticky header */
header {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
}

Relative positioning is often used on a parent so that absolutely-positioned children can be placed within it. Without a positioned ancestor, an absolute element falls back to the viewport.

Key Ideas

  • static is the default; offsets have no effect.
  • relative shifts from normal position; absolute positions against the nearest positioned ancestor.
  • fixed positions against the viewport.
  • z-index controls stacking order and only applies to positioned elements.

Layout Control

The display property — the switch that decides how an element behaves.

The display property is the most important property in CSS layout. Every element's behaviour — block, inline, inline-block, flex, grid, table — is set by it. Changing display changes how the element participates in flow.

block elements take the full width of their parent and start on a new line. inline elements sit in the flow of text and ignore width/height. inline-block blends the two — it sits inline like text but accepts width and height. none removes the element from the page entirely.

/* Block-level */
div { display: block; }

/* Inline */
span { display: inline; }

/* Inline-block — respects width/height */
.btn {
  display: inline-block;
  padding: 10px 20px;
}

/* Hidden */
.hidden { display: none; }

/* Table behaviour on a div */
.table-div { display: table; }
.table-row { display: table-row; }
.table-cell { display: table-cell; }

Unlike visibility: hidden, display: none removes the element from layout entirely — it takes up no space. That distinction matters for menus, modals, and keyboard focus.

Key Ideas

  • display controls how an element behaves in layout.
  • block, inline, and inline-block cover the classic modes.
  • display: none removes the element from layout entirely.
  • display: table gives table behaviour to divs.

Grid

Two-dimensional layout, at last.

CSS Grid lays out content in rows and columns simultaneously. Apply display: grid to a parent and its immediate children become grid items. grid-template-columns and grid-template-rows define the tracks.

Items are placed by grid-column and grid-row — either by line number, or by named areas. grid-gap creates gutters between cells. Grid can be nested inside Flexbox and vice versa; they are complementary, not competing.

.container {

  grid-template-rows: 50px 50px;
  gap: 10px;
}

.item3 { grid-column: 1; grid-row: 2; }
.item4 { grid-column: 2; grid-row: 2; }

Tables

Borders, spacing, and the algorithm that sizes cells.

CSS provides several properties specifically for HTML tables. table-layout chooses between auto (the default, where content determines column widths) and fixed (where the table's declared width wins, and cells clip their content).

border-collapse merges adjacent cell borders into one or keeps them separate. When separate, border-spacing controls the gap. empty-cells decides whether cells with no content show their borders. caption-side moves the table caption above or below the table.

  font-style: italic;

Tables have not changed much since CSS2, and for good reason: the HTML table element is still the right tool for tabular data. Use CSS Grid for layout and reserve tables for actual tables.

Transitions

Smooth changes between two states.

A transition animates a property change between two states — hover to non-hover, small to large, red to green. The shorthand transition: background-color 1s; sets the property, duration, timing function, and delay in one declaration.

The transition-timing-function controls the easing curve. ease, linear, ease-in, ease-out, and ease-in-out cover most needs; cubic-bezier() gives complete control. steps() creates discrete jumps rather than smooth changes.

/* One property */

  width: 150px;
  height: 150px;
  background-color: red;
  transition: background-color 1s;
}
div:hover {
  background-color: green;
}

/* Multiple properties */
.box {
  transition: height 1s, width 500ms;
}

Not every property is transitionable — display and visibility famously are not, and neither are keyword values like auto. The unit must remain consistent for the transition to interpolate.

  • Transitions animate property changes between two states.
  • The shorthand sets property, duration, timing, and delay.
  • cubic-bezier() gives fine-grained easing.
  • Not every property is transitionable.

2D Transforms

Rotate, scale, skew, and translate — the geometry of CSS.

The transform property applies geometric operations to an element. rotate() turns it; scale() resizes it; skew() slants it; translate() moves it. matrix() gives the full affine transformation in one function.

Transforms do not affect layout — neighbouring elements see the element at its original position. That makes transform animations smooth. The origin of the transform can be changed with transform-origin; the default is the element's centre.

.rotate  { transform: rotate(45deg); }
.scale   { transform: scale(0.5, 1.3); }
.skew    { transform: skew(20deg, -30deg); }
.translate { transform: translate(200px, 50%); }

/* Chained transforms apply in order */
.chained {
  transform: rotate(15deg) translateX(200px);
}

/* Change the origin */
.origin {
  transform-origin: 0 0;
  transform: rotate(30deg);
}

Transforms can be chained, and the order matters: rotate() translate() means rotate first, then translate along the rotated axis.

Key Ideas

  • Transforms apply rotate, scale, skew, and translate.
  • Transforms do not affect layout.
  • transform-origin changes the pivot point.
  • Chained transforms apply in declared order.

Blur, brightness, contrast, and the photographic effects in CSS.

CSS Variables

Reusable values that cascade, change with media queries, and make themes possible.

Custom properties — often called CSS variables — are declared with a double-dash prefix and read with var(). They cascade like any other property, so a variable defined on :root is available to the entire document; a variable defined inside a rule is available only within that rule's subtree.

Variable names are case-sensitive. They can hold any CSS value — colours, dimensions, even whole declarations. Empty values are legal, but a variable used outside var() is not. Units belong on the value, not on the var() call.

:root {
  --red: #b00;
  --blue: #4679bd;
  --grey: #ddd;
  --gap: 10px;
}

.box {
  color: var(--red);
  border: 1px solid var(--red);
  padding: var(--gap);
}

/* Variables can be redefined in a media query */
@media only screen and (max-width: 767px) {
  :root {
    --gap: 4px;
  }
}

Because they cascade, variables can be overridden per component without touching the definition. That is how theming works in modern CSS.

Key Ideas

  • Custom properties are declared with -- and read with var().
  • They cascade and inherit like ordinary properties.
  • Units belong on the value, not on the var() call.
  • Redefining a variable in a media query updates everything that uses it.

Inheritance

Properties that flow from parent to child — and how to force the ones that do not.

Some CSS properties inherit automatically. Set color on a parent and every child gets it. The same goes for font-family, font-size, line-height, text-align, and visibility. Others — margin, padding, background, display, border — do not.

The inherit value forces a property to take the parent's computed value. That is how you pull a padding or margin down into a child when the browser would otherwise default it to 0.

#myContainer {
  color: red;
  padding: 5px;
}

/* Children inherit color automatically */

/* Force padding to inherit */
#myContainer p {
  padding: inherit;
}

Inheritance keeps stylesheets short. When you find yourself repeating a colour or font across every child, set it once on the parent instead.

Key Ideas

  • Font, colour, text-align, line-height, and visibility inherit automatically.
  • Margin, padding, background, display, and border do not.
  • inherit forces any property to take the parent's computed value.
  • Use inheritance to keep stylesheets short.

CSS Image Sprites

One image, many icons — fewer requests, faster pages.

An image sprite is a single image file that packs many smaller images into a grid. CSS can then show one cell at a time by setting background-image to the sprite and background-position to the negative offset of the desired cell. One HTTP request serves every icon in the sheet.

.icon3 { background-position: -40px 0px; }

Clipping and Masking

Cutting shapes out of elements — and fading them through masks.

Clipping and masking both hide parts of an element, but they work differently. Clipping defines a vector path — anything outside the path is transparent. Masking uses an image or gradient to decide which parts of the element are visible.

clip-path accepts shapes: circle(), ellipse(), polygon(), and URL references to SVG paths. mask-image takes an image or gradient — a linear gradient from white to transparent fades the element out, a radial gradient punches a hole.

/* Clip to a triangle */
.tri {
  width: 200px;
  height: 200px;
  background: teal;
  clip-path: polygon(0 0, 0 100%, 100% 50%);
}

/* Mask with a gradient fade */
.fade {
  width: 200px;
  height: 200px;
  background: url('photo.jpg');
  mask-image: linear-gradient(to right, white, transparent);
}

Masks and clips can be combined with transitions to create reveal effects, but browser support for masking is still uneven — provide fallbacks.

Key Ideas

  • clip-path defines a vector clipping path.
  • mask-image reveals the element through an image or gradient.
  • Shapes include circle(), polygon(), and gradients.
  • Masking support is uneven — provide fallbacks.

CSS Object Model (CSSOM)

How the browser turns stylesheets into a model it can render and modify.

The browser parses your CSS into a tree of rules called the CSSOM, just as it parses HTML into the DOM. It then combines the two into a render tree that the browser can paint. That is the pipeline: HTML → DOM, CSS → CSSOM, DOM + CSSOM → render tree → screen.

JavaScript can reach into the CSSOM to add, remove, or change rules. document.styleSheets[0].cssRules returns the rule list; insertRule() appends a new rule; deleteRule() removes one. This is how runtime theming and dynamic stylesheets are implemented.

var sheet = document.styleSheets[0].cssRules;
var end = sheet.length - 1;

sheet.insertRule(
  "body { background-image: url('bg.png'); }",
  end
);

The CSSOM is also what devtools show you when you inspect an element's computed styles. Understanding it makes "why is my style being overridden?" easier to answer.

Key Ideas

  • The browser builds a CSSOM from parsed stylesheets.
  • DOM plus CSSOM produces the render tree.
  • JavaScript can insert or delete CSS rules through the CSSOM.
  • Devtools' computed styles come from the CSSOM.

Stacking Context

Why z-index sometimes feels broken.

Elements on a page are rendered in a 3D coordinate system, with the z-axis pointing toward the viewer. z-index controls each element's position along that axis — but only within its stacking context.

A stacking context is a group of elements that stack together as a unit. The root element creates one; so do positioned elements with a z-index, elements with opacity less than 1, transform, filter, and several other properties. Once a child context closes, its z-index is resolved relative to its parent, not to the root of the page.

#div1 { position: relative; z-index: 5; }
#div2 { position: relative; z-index: 2; }
#div3 { position: absolute; z-index: 4; }

/* Children of #div3 are stacked within #div3,
   not against #div1 and #div2. */
#div4 { position: relative; z-index: 6; }

The classic symptom of a stacking problem is a tooltip whose z-index of 9999 still sits under a modal, because the two elements live in different contexts and the modal's context has a higher overall z-index.

Key Ideas

  • A stacking context groups elements that stack as a unit.
  • z-index only applies within its stacking context.
  • Many properties — opacity, transform, filter — create new contexts.
  • Nested contexts explain many "z-index doesn't work" bugs.

Block Formatting Contexts

The invisible container that changes how floats and margins behave.

A block formatting context (BFC) is a region in which block-level boxes lay out independently of what happens outside. Inside a BFC, floats do not escape, margins do not collapse with outside elements, and the region contains its own floats.

Several properties create a BFC. The most useful is overflow with any value other than visible. Others include float, position: absolute/fixed, display: flow-root, and display: inline-block.

/* Float a picture, then contain it */
img {
  float: left;
  width: 100px;
  margin-right: 10px;
}

/* Without BFC, this parent collapses */
.div1 { background: #f1f1f1; }

/* With BFC, the parent contains the float */
.div2 {
  background: #f1f1f1;
  overflow: hidden;
}

Before Flexbox and Grid, the BFC was the main tool for containing floats. It remains essential for understanding margin collapsing and for fixing layout bugs in older codebases.

Key Ideas

  • A BFC contains its own floats and prevents margin escape.
  • overflow: hidden is the easiest way to create one.
  • float, position: absolute, and display: flow-root also create BFCs.
  • BFCs explain many float- and margin-related layout bugs.

Vertical Centering

Older techniques still appear in legacy code. display: table plus display: table-cell; vertical-align: middle; works in any browser. line-height equal to the container height centres a single line of text. /* Flexbox — the modern choice */

.centered {

  top: 50%;
  left: 50%;

.outer { display: table; height: 100%; width: 100%; }
.inner {
  display: table-cell;

  text-align: center;

Object Fit and Placement

How images and video behave inside a fixed-size box.

object-fit decides how an <img> or <video> fills its content box. fill stretches to fit, ignoring aspect ratio. contain fits entirely inside the box, preserving aspect ratio. cover fills the box entirely, cropping if necessary. none ignores the box size. scale-down uses whichever is smaller between none and contain.

object-position controls where the object sits inside its box — useful with cover, where parts of the image are cropped.

/* Fill and crop, keeping aspect ratio */
.hero img {
  width: 100%;
  height: 300px;
  object-fit: cover;
  object-position: center top;
}

/* Fit entirely, letterbox if needed */
.thumb img {
  object-fit: contain;
}

Object-fit is a huge time-saver for responsive images and media grids. Before it existed, developers relied on background images, which could not be <img> elements with alt text — a significant accessibility loss.

Key Ideas

  • object-fit controls how an image fills its box.
  • cover fills and crops; contain fits and letterboxes.
  • object-position sets the anchor point of the fitted object.
  • Object-fit replaces many background-image tricks, with alt text intact.

CSS design patterns

As CSS grows, naming becomes the hard part. BEM — Block, Element, Modifier — is a naming convention that keeps selectors readable and specificities flat. A block is a standalone component (a card, a menu); an element is a part of a block (a title, a list item); a modifier is a variant (disabled, highlighted).

Classes follow a pattern: .block, .block__element, .block--modifier, and .block__element--modifier. Each class stands alone, so specificity stays at a single class level.

.form { }                /* Block */
.form--simple { }        /* Block + modifier */
.form__input { }         /* Element */
.form__submit { }        /* Element */
.form__submit--disabled { }

BEM is not the only answer — OOCSS and SMACSS offer different structures — but the underlying idea is the same: make classes mean one thing, so styling stays predictable as the project grows.

  • Class names follow .block__element--modifier.
  • Each class stands alone, keeping specificity low.
  • Naming conventions make CSS scale beyond a few pages.

Normalizing Browser Styles

Every browser applies a default stylesheet to HTML. Headings have margins, lists have padding, links are blue and underlined. Because these defaults are not identical across browsers, a page can look subtly different in each. Two strategies address this: resets and normalizers.

html {
  font-family: sans-serif;
  line-height: 1.15;
  -ms-text-size-adjust: 100%;
  -webkit-text-size-adjust: 100%;
}
body {
  margin: 0;
}

Either strategy saves you from fighting the browser every time you style a page. Add one to the top of your stylesheet — or import it — and start designing from a consistent base.

Key Ideas

  • Browsers ship different default stylesheets.
  • A reset zeroes out defaults; a normalizer evens them out.
  • normalize.css is the modern favourite.

Performance

Smooth animation is a choice — and CSS gives you the tools.

Not every CSS animation is created equal. Animating left and top forces the browser to recalculate layout on every frame. Animating transform and opacity lets the browser offload the work to the GPU. The result is the difference between 12ms and 1.3ms of per-frame work.

will-change: transform, opacity hints the browser to prepare paint layers in advance. Used sparingly, it improves animation performance; used everywhere, it can cause memory problems and layout bugs.

/* Slow: triggers layout every frame */
#box {
  position: absolute;
  left: 0;
  top: 0;
  transition: left 0.5s, top 0.5s;
}
#box.active {
  left: 100px;
  top: 100px;
}

/* Fast: GPU-accelerated */
#box {
  position: absolute;
  left: 0;
  top: 0;
  transition: transform 0.5s;
  transform: translate3d(0, 0, 0);
  will-change: transform;
}
#box.active {
  transform: translate3d(100px, 100px, 0);
}

Performance is not just a developer concern. A janky animation feels broken, and users notice. The habit of animating transforms first, and only touching layout when necessary, is the single biggest performance win available to a CSS author.

Key Ideas

  • Animating left and top triggers layout; transform and opacity do not.
  • GPU-accelerated properties keep animation at 60fps.
  • will-change hints at upcoming animation — use sparingly.
  • Choosing transforms is the biggest performance win available in CSS.

Selects elements based on the presence or value of an attribute. Examples: [disabled], [type="checkbox"], [href$=".pdf"].
Block formatting context (BFC)
A region in which block-level boxes lay out independently. Inside a BFC, floats are contained and margins do not collapse with outside elements. Created by overflow: hidden, float, position: absolute/fixed, and display: flow-root.
Block-level element
An element whose default display is block. It takes the full width of its parent and starts on a new line. Examples: div, p, h1.
Box model
The four-part structure of every element: content, padding, border, and margin. The full width is content + padding + border + margin.
Box-sizing
Controls whether width and height include padding and border. content-box (default) does not; border-box does.
Cascade
The algorithm that resolves conflicts between competing CSS rules. It considers origin, specificity, and source order.
Class selector
Selects elements with a given class. Written as .name and matches every element with class="name".
Clearfix
A technique to make a parent contain its floated children, usually via a ::after pseudo-element with clear: both.
Combinator
A character that expresses a relationship between selectors: descendant (space), child (>), adjacent sibling (+), general sibling (~).
Computed value
The final value of a property after all relative values have been resolved — for example, an em converted to pixels.
CSSOM
The CSS Object Model: the browser's parsed representation of stylesheets, analogous to the DOM. JavaScript can read and modify it.
Custom property
A CSS variable declared with a -- prefix and read with var(). Custom properties cascade and inherit.
Declaration
A single property: value pair inside a rule's declaration block.
Display
The property that controls how an element behaves in layout: block, inline, inline-block, flex, grid, none.
Em
A relative length unit equal to the element's current font-size (or the parent's, if not set). Values compound through nesting.
Flexbox
A one-dimensional layout model (display: flex) that distributes space among items along a row or column.
Float
Pushes an element to one side (left or right) and lets content flow around it. Floats were once used for layout; today they are best for text wrapping.
Grid
A two-dimensional layout model (display: grid) that lays out items in rows and columns simultaneously.
ID selector
Selects the single element with a given ID. Written as #name and should be unique on the page.
Inheritance
The mechanism by which some properties (colour, font, line-height) pass from parent to child automatically. Non-inherited properties can be forced to inherit with inherit.
Inline element
An element whose default display is inline. It sits in the flow of text and ignores width and height. Examples: span, a, em.
Inline-block
A display value that combines inline flow with block-like width and height control.
Margin collapsing
The rule that two adjacent vertical margins merge into the larger of the two. Horizontal margins do not collapse.
Media query
An @media rule that applies CSS only when certain screen conditions (width, orientation, resolution) are met. The backbone of responsive design.
Normalizer
A stylesheet that evens out browser default styles across browsers, keeping useful defaults. Example: normalize.css.
Pseudo-class
A selector that matches elements by state or position: :hover, :focus, :first-child, :nth-child(3).
Pseudo-element
A selector that styles a sub-part of an element: ::before, ::after, ::first-letter, ::first-line.
Rem
A relative length unit equal to the root (<html>) font-size. Unlike em, rem does not compound.
Reset
A stylesheet that zeroes out all browser default styles. Example: Eric Meyer's Reset CSS.
Rule
A selector plus a declaration block: h1 { color: green; }.
Selector
The part of a rule that names which elements to style. Examples: div, .card, #main.
Shorthand
A property that sets several longhands at once, such as margin, font, or background.
Specificity
The weight of a selector, scored on three axes: IDs (A), classes/attributes/pseudo-classes (B), and types/pseudo-elements (C). Higher specificity wins.
Stacking context
A group of elements that stack together as a unit. z-index values are resolved within their stacking context, not across the whole page.
Transform
A property that applies geometric operations: rotate(), scale(), skew(), translate(). Transforms do not affect layout.
Transition
A property that animates the change between two states of another property over a given duration and easing curve.
Vendor prefix
A browser-specific prefix (-webkit-, -moz-, -ms-, -o-) used for properties that are not yet standardised.
Viewport
The visible area of the browser window. Viewport units (vh, vw, vmin, vmax) are percentages of it.
Z-index
The property that controls stacking order among positioned elements. Higher values appear in front. Only applies within a stacking context.
